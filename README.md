# Лабораторная работа: Проектирование приложений на PHP (Layered Architecture)

## 1. Описание предметной области и задачи
Цель работы — спроектировать систему для автоматизации работы библиотеки с использованием архитектурного паттерна Layered Architecture (Слоистая архитектура).

Основные возможности системы:
*   **Каталог книг:** Просмотр всех книг с указанием автора, года издания, жанра, ISBN и количества доступных экземпляров.
*   **Управление читателями:** Регистрация новых читателей (ФИО, номер читательского билета, телефон, email).
*   **Выдача книг:** Проверка наличия свободного экземпляра. После успешной выдачи создаётся запись с датой выдачи и планируемой датой возврата.
*   **Возврат книг:** Закрытие записи о выдаче и возвращение экземпляра в фонд библиотеки.
*   **Отчеты:** Получение истории всех выдач, поиск книг, получение списка книг конкретного читателя и списка просроченных книг.

## 2. Архитектура приложения (Layered Architecture)
В соответствии с заданием архитектура разделена на четыре основных слоя. Каждый слой имеет свою зону ответственности и зависит только от слоя, находящегося ниже.

┌────────────────────────────────────────────────────────┐
│                PRESENTATION LAYER (Экран)              │
│   Пассивные страницы и формы (index.php).              │
│   Никаких вычислений и запросов к БД. Только показ     │
│   данных и передача кликов/ввода во ViewModel.         │
└───────────────────────────▲────────────────────────────┘
                            │ Вызовы методов сервиса
┌───────────────────────────▼────────────────────────────┐
│                APPLICATION LAYER (Логика)              │
│   Оркестрация сценариев (LibraryService).              │
│   Управляет вызовами сущностей и репозиториев.         │
└───────────────────────────▲────────────────────────────┘
                            │ Вызовы методов / DTO
┌───────────────────────────▼────────────────────────────┐
│                 BUSINESS LAYER (Домен)                 │
│   Сущности (Book, Author, Reader, BookLoan).           │
│   Бизнес-правила (например, проверка isAvailable()).   │
└───────────────────────────▲────────────────────────────┘
                            │ Запросы на сохранение/чтение
┌───────────────────────────▼────────────────────────────┐
│                DATA ACCESS LAYER (Данные)              │
│   Репозитории (BookRepository, LoanRepository и др.).  │
│   ВСЕ SQL-запросы находятся исключительно здесь.       │
└────────────────────────────────────────────────────────┘

### Слой Presentation (Представление)
Отвечает за отображение интерфейса пользователя. В нашем случае это HTML-форма и обработчик POST-запросов (`src/Presentation/index.php`). Слой не содержит SQL-запросов и бизнес-логики.

### Слой Application (Приложение)
Класс `LibraryService`. Выступает посредником. Он получает данные от Presentation Layer, вызывает методы Business Layer для проверки правил и обращается к Data Access Layer для сохранения или получения данных.

### Слой Business (Бизнес-логика)
Содержит сущности `Book`, `Author`, `Reader`, `BookLoan`. Здесь находятся правила предметной области (например, метод `isAvailable()` у книги проверяет, больше ли нуля доступных экземпляров).

### Слой Data Access (Доступ к данным)
Репозитории (`BookRepository`, `ReaderRepository`, `LoanRepository`). Здесь инкапсулирована вся работа с базой данных (SQLite). В этом слое находятся только SQL-запросы (INSERT, SELECT, UPDATE).

## 3. UML-диаграммы
В папке `docs/` находятся файлы с Mermaid-разметкой, которые GitHub автоматически отрисовывает как диаграммы:
*   `docs/uml-class.md` — Диаграмма классов (отражает сущности, их свойства и связи между слоями).
*   `docs/uml-sequence.md` — Диаграмма последовательности (сценарий выдачи книги от пользователя до базы данных).

## 4. Описание алгоритмов
**Алгоритм проверки доступности и выдачи книги**
Логика работы: Перед выдачей книги система должна удостовериться, что в библиотеке есть физический экземпляр.
1. Application Layer запрашивает у Data Access Layer информацию о книге по её ID.
2. Business Layer проверяет свойство `availableCopies`. Если оно равно 0, выбрасывается исключение.
3. Если экземпляры есть, Application Layer дает команду Data Access Layer уменьшить `availableCopies` на 1 и создать запись о выдаче (`BookLoan`).

**Алгоритм возврата книги**
Логика работы: При возврате книги запись о выдаче закрывается, а книга снова становится доступной.
1. Application Layer получает ID записи о выдаче.
2. Data Access Layer находит эту запись, меняет флаг `isReturned` на TRUE и возвращает ID книги.
3. Application Layer дает команду увеличить `availableCopies` этой книги на 1.

## 5. Спецификация интерфейсов и бизнес-правила
*   **Запрет выдачи при отсутствии:** Нельзя выдать книгу, если `availableCopies <= 0`.
*   **Изоляция SQL:** Все запросы к базе данных (SQLite) выполняются строго внутри классов в папке `src/DataAccess/`. Слой представления и бизнес-логики ничего не знают о структуре таблиц.
*   **Регистрация читателя:** Номер читательского билета (`ticket_number`) должен быть уникальным (проверяется на уровне БД).

## 6. Как запустить проект
1. Убедитесь, что у вас установлен PHP (версия 8.0+).
2. В терминале в корне проекта выполните команду:
   `php -S localhost:8000 -t src/Presentation`
3. Откройте браузер и перейдите по адресу `http://localhost:8000`.
4. База данных SQLite (`library.sqlite`) создастся автоматически при первом запуске.
